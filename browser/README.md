`--trace-windows` records actual window geometry imports and the observed main-thread stack at moves. A capture request can also contain `"screenshot":true` and `"input":[{"type":"click","x":600,"y":500,"holdMilliseconds":1000},{"type":"text","text":"example"}]`. Coordinates are intrinsic canvas pixels; input uses real browser events. A click holds the button for 80 ms by default; `holdMilliseconds` accepts integers from 0 to 5000, allowing a slower original frame to observe the press. The entire batch is validated before input is sent. New evidence records text lengths and redacts runtime key values; the locally supplied request file still contains its input. Earlier captures may contain key values. Move the pointer and allow a frame interval before clicking: the original UI uses its cached per-frame mouse position. These controls do not modify guest memory. Screenshot timeouts are recorded and subsequent capture work continues.

Long captures write `progress.json` every ten seconds and screenshots every minute. `capture_probe.js` records x86 stacks, sparse memory commitments, graphics/socket state, and original Lua state when recognized; these reads of shared memory are not atomic. During a run, a `request.json` in its report directory can request additional guest memory or resident text logs, for example `{"id":"inspect-1","files":true,"memory":[{"address":865337344,"size":64}]}`. The capture writes `response.json`. A request with `"finish":true` saves the final evidence and ends that capture; `"extendSeconds":600` extends it by ten minutes (up to one hour per distinct request). These controls exist only in the local capture process.

`"drawCapture":{"maxDraws":256,"maxBytes":16777216}` arms observation of one submitted frame after the next Present. A later request with `"drawCapture":true` saves the current observation in `draws-NNN.json`. It copies actual geometry, shaders and constant bytes before scratch reuse; texture pixels are omitted, so this is not a complete scene replay. Programmable vertex draws are selected by default; `"programmableOnly":false` also includes fixed vertex draws. Limits stop capture explicitly, and copying changes timing. Commands and guest state are not replaced. Network snapshots retain counts and endpoints for at most 32 outgoing UDP routes, with an overflow count and no packet payloads.

For a write investigation, `--watch-pointer 33471d38 --watch-offset 18c` arms the existing debugger at that pointer's target plus the given offset when initialized; both values are hexadecimal. A fixed guest address can instead be watched with the launch URL `?watch=35477718`. Worker reports include the observed value and the executing instance's registers and stack. Watchpoints alter scheduling and disable execution optimizations; a shared-memory change observed by another thread does not identify that thread as the writer. These diagnostic runs are labeled separately from ordinary captures. A capture request can also supply an ordered `breakpoints` array, with each point containing an original guest `address` and bounded `memory` reads (`register`, optional `indirect` pointer offsets, optional final `offset`, and `size`). Each hit records the executing Worker's registers and reads before it resumes, then arms the next point. Other workers may still change shared memory. `"breakpointScope":"all"` also arms existing guest threads and newly created Workers before their first execution. Plans automatically disable after their last hit; an empty array clears an unfinished plan. No guest instructions or data are replaced.
