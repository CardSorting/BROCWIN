# 0015 — Failed heap reservation rollback (source-only)

Date: 2026-10-11. [Closeout](../closeout.md) · [Threads and memory](../threads-memory.md) · [Evidence](../../reports/performance/heap-reservation-20261011/README.md)

The retained deterministic fixture demonstrates that `$heap_large_alloc` reserves a range, retries a failed commit after reclaiming retired empty arenas, then returns zero without releasing the provisional reservation. Fallback releases its separate reservation; the unregistered primary range remains outside arena reclamation. This is a resource-lifetime reproduction, not evidence of an original-client leak or a measured startup cause.

The final working [helper snapshot](../frozen-sources/10-helpers.wat) calls the existing release helper after the second failed commit before returning to fallback. The [fixture snapshot](../frozen-sources/test-heap-reservation-rollback.js) uses two initialized shared-memory instances, real live guards and failed allocations. It compares reservation/mapping/cursor/arena/live-byte state, then requires a disjoint writable 2 MiB allocation and reclaimable successful allocations.

The [preserved compiled control](../generated/evidence/heap-reservation-control.json) fails both cases: four above-backing-extent refusals and three refusals under live-backing pressure accumulate reservations. The [source-compiled candidate](../generated/evidence/heap-reservation-source.json) passes both. [Twelve affected source suites](../generated/evidence/heap-reservation-suites.json) record exit code zero, completed at 20:38:40.353 UTC while shutdown was being coordinated. The helper hash matches before and after the batch; the retained JSON lists every command, source and log hash.
