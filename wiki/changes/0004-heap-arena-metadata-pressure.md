# 0004 — Reclaim empty arenas at the metadata limit

[Wiki home](../README.md) · [Memory](../threads-memory.md) · [Issues](../issues.md)

Date: 2026-10-10. Contributor: Codex /root, no delegated agents. The client port remains incomplete. Native servers, SQL schemas and persistence code are unchanged.

The [sealed replay 210727](../../reports/browser/20261010T210727Z/review.json) reached original defeat rewards, returned to Ruben, and entered a second dungeon in the same browser. Loading its second area failed at `heap_arena_register`, followed by worker traps and a main-thread `setlocale(4, NULL)` trap. The last sample contained 722 committed sparse mappings and 853,131,264 sparse bytes, below available backing. OOM reason 4 identifies the separate 1,024-record heap arena table; its former host message incorrectly named the virtual map table. This capture did not measure the live/free arena distribution.

Existing reclamation ran on reservation or backing failure, but registration failure released the provisional mapping and returned OOM without trying reclamation. [10-helpers.wat](../../tools/wine-assembly/src/10-helpers.wat) now tries the existing retired-empty-arena reclamation and retries registration once. It preserves the record limit, live allocations, ownership checks and genuine exhaustion. Region owner metadata follows the renamed registration body. The host OOM message now names `HEAP_ARENAS` accurately.

[The regression](../../tools/wine-assembly/test/test-heap-arena-metadata-pressure.js) fills all 1,024 records through real allocations across shared Wasm instances. It first verifies refusal while every arena remains live, then frees 341 retired arenas and requires small and large allocations to succeed while preserving every live guard. The preserved old module fails this check. The canonical candidate passes it and eight existing heap/reservation regressions. [Validation](../../reports/heap-metadata-20261010T232432Z/validation.json) retains commands, test hashes, build identities and control logs.

From the dependency directory, run `node test/test-heap-arena-metadata-pressure.js build/wine-assembly.wasm`; use the [build runbook](../build-recovery.md) to rebuild and prepare the integrated application. The capture observer also records an asynchronous, read-only arena census to distinguish metadata pressure from backing pressure on the next replay. This is diagnostic sampling, not an atomic ownership decision.

The [233733 candidate replay](../../reports/browser/20261010T233733Z/review.json) verified login, saved character, Ruben movement, inventory, Options open-close and first-area A/S/basic combat. It ended while the guest was executing because the capture harness raised `PermissionError` reading `request.json`. Request 40 was never applied. All 242 source identities, both modules and patch match; 39 manual images and the final image were reviewed. This is a harness interruption, not evidence of a guest trap or corrected second-cycle loading.

[capture.py](../../browser/capture.py) now retries unavailable or incomplete control-file reads on the next ordinary poll without consuming a request ID or closing the game. [The focused regression](../../browser/test_capture_input.py) reproduces the permission error before the fix and passes afterward, including disappearance, incomplete JSON and later successful delivery. [Harness validation](../../reports/heap-metadata-20261010T232432Z/capture-control-validation.json) preserves results and hashes. The precise external source of the file access denial remains unknown; the repair prevents that observed diagnostic I/O error from ending gameplay. The compiled runtime was unchanged. The subsequent [000646 replay](../../reports/browser/20261011T000646Z/review.json) recovered five denied reads, then ended after a separate transport loss; [change 0005](0005-shared-wire-consumption.md) continues that diagnosis.

The earlier [195820 boss exit](../../reports/browser/20261010T195820Z/review.json) occurred before victory/results. Its host `exit(-1)` label does not identify which original API called it; the later static caller analysis is only a hypothesis. The 210727 replay did not reproduce that exit. Its later `setlocale` failure has no established causal relationship to allocation failure. Neither is hidden by this repair.

The 210727 reward panel and guarded SQL agree on +3,837 EXP and +84 ED after defeat. That proves the defeat reward/return route on its preserved build, not victory or successful revival. All 11 required acceptance steps still need to pass together on the final candidate.
