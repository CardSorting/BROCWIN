# 0007 — Keep sparse allocations outside the image translation window

[Wiki](../README.md) · [Memory](../threads-memory.md) · [Acceptance](../acceptance-session.md)

Date: 2026-10-11. Contributor: Codex /root, no delegated agents. Original game instructions/assets, native servers, configuration, SQL schemas and persistence logic are unchanged.

[Replay 053950](../../reports/browser/20261011T053950Z/review.json) completed one Tree of El victory, rewards and interactive town return, then cleared the first area of a second cycle. The next-area load overwrote HEAP_ARENAS with animation matrices. Its failure-time count is `0x3f800000` (float 1.0), followed by 2,202 OOM reports and terminal API traps. This supersedes an inference of legitimate metadata exhaustion for this specific run, not the preserved facts of earlier runs.

The original X2 image base is `0x32830000`. Its direct affine translation covers guest `0x3281e000..0x3a81e000`, including runtime-private storage. Sparse placement keeps a floor of `0x10000000` to retain address space below high images, but failed to exclude the intervening direct window. Once repeated loading descended into it, ordinary guest writes could resolve onto runtime tables rather than their allocated sparse backing. The [preserved control and diagnosis](../../reports/high-image-20261011T071500Z/diagnosis.json) reproduce the exact allocator-count corruption through real returned heap and mapped-view allocations. The capture did not retain the individual overwriting instruction; the fixture establishes the allocation/translation contract failure.

[10-helpers.wat](../../tools/wine-assembly/src/10-helpers.wat) now reports the direct window as occupied in the existing placement search, for both search directions. It retains usable capacity below the image and does not increase any memory/table limit. The exclusive boundary is derived from the affine delta, because `w2g` at that endpoint already consults sparse backing. The first attempted implementation used that incorrect endpoint conversion; regressions rejected it before browser preparation. Its module, sources and failures remain in `attempt1`.

Allowing valid lower allocations also exposed a dependent HeapReAlloc assumption: pointer order below the low-heap base was treated as foreign ownership. [09a0-handlers-base.wat](../../tools/wine-assembly/src/09a0-handlers-base.wat) now checks the existing arena owner before taking that path. The focused control fails an in-place shrink of a valid lower block. The correction must preserve content and zero the grown tail. No new allocator architecture or guest game behavior is introduced.

Regression sources: [compiled-module high-image placement](../../browser/test_high_image_allocations.cjs), [owned lower-block reallocation](../../browser/test_high_image_realloc.cjs), and the extended dependency [placement floor test](../../tools/wine-assembly/test/test-virtual-alloc-floor-direct-window.js). They cover the original high image, another high image and a normal image, heap/view/section routes, both placement directions and lower address capacity.
